# Steinoak State Research SOP

**Version 1.63, 2026-10-08 (1.0 approved by Taylor).** This is the one procedure every state pass follows. It replaces the "Instructions for the next state" list (instructions 1–66) in `lease-clause-decision-log-named-topic-checklist.md`, the method lessons scattered through the state logs, and Addenda K and L of `lease-clause-decision-log-architecture-review.md`. Each rule gives its source in brackets so the history can be traced; the reasoning lives there, not here.

**How this document is kept current**
- Rule numbers never change. A retired rule stays listed as "Retired, see rule N".
- **Who finishes what.** Claude Desktop's pass is finished when it delivers the handoff in Part 4. Everything after that is Claude Code's sync (Part 5), and Desktop doesn't need to track it.
- At sync, Claude Code reads the handoff's "Proposed SOP changes" list and the log for other lessons. It adds each one here as a rule or rejects it with a one-line reason in the change log. The sync isn't done until that's happened.
- **Claude Code assigns every rule's tag, never Claude Desktop.** **[Retro]** means the rule changes what a finished state's content should look like; **[Fwd]** means it's process only and applies to future work. When Claude Code adds a [Retro] rule, it adds a row to the conformance table and schedules a targeted check of each finished state against that rule only (a scalpel, not a re-audit). Claude Code does the checks it can from the repo; a check that needs statute text goes to that state's Desktop chat as a short, scoped prompt. Desktop runs a retro check only when handed one of those prompts.
- Claude Desktop reads this document at the start of every state pass and every circle-back. Claude Code checks each handoff against it.

## Part 1. Standing rules

1. **No re-audits.** A finished state is never re-scrubbed as a whole. Going back to fix or re-verify a specific row or topic is welcome: name it, say why, propose the narrow fix. Don't propose, plan or park anything "for the re-audit". [Taylor 2026-09-26; checklist 22] [Fwd]
2. **Never ask Taylor for landlord experience outside Colorado.** His experience is Colorado-only and already in the CO research. Scenario screens are generated by Claude (rule 23). [Taylor 2026-09-27] [Fwd]
3. **State law only.** Flag a municipal ordinance when you find one, but don't resolve it or let it into state-level clause text. [checklist 20] [Fwd]
4. **Coverage is "state law, verified", never "all law for the property".** There is no attorney review; say what was read and where the search stopped. [CO scope box; L.7] [Fwd]
5. **"Verified" is earned per state.** A blank `states` field means verified nowhere, and "universal" would need all 50 states verified. Tagging a second state needs the same primary-source rigor as the first. [CLAUDE.md Aug 2026] [Fwd]
6. **One curated answer per topic.** Where two versions of a clause reflect a legal-strategy choice rather than a fact about the law, ship one and keep the other inactive (`is_active` FALSE), with a note. Where the versions reflect a fact about the property or tenancy instead, ship both active in one `choice_group`, with the version lawful for everyone as `is_default` (rule 32), as `ca-tpa-coverage` and `co-part13-coverage` do. [WY Safe Homes; CO retro 6] [Fwd]
7. **The CSV is the fact; a log entry is not a library change.** If the log says a row exists, the row must exist. After writing rows, check the CSV itself. [L.3; ND lesson 7] [Fwd]
8. **One Claude Desktop chat per state, reused for every circle-back.** At the start of any work in that chat: delete old output files (say what you deleted), treat the files Taylor uploads for this task as the only source of truth, and say so wherever something earlier in the chat conflicts with them. Name output files for their task (`lease-clauses-PA-delta.csv`), never a bare version number. [checklist 43] [Fwd]
9. **Settings:** Opus, high effort. Turn on research mode only for proof-of-absence confirmation, ambiguous or conflicting statute language, or a cross-chapter gap search, and say when and why you turn it on. [OH kickoff] [Fwd]
10. **When a question is about how the app behaves, ask Claude Code to run the code.** Don't reason from documentation, including CLAUDE.md and these logs; they have been wrong about the app before. [checklist 23] [Fwd]
76. **Work it out yourself first; if you're unsure, ask Taylor in the chat, right then.** Settle legal and drafting judgments yourself where you're confident, and record the reasoning in the log. Narrowing an optional clause, adding a saving sentence and choosing which tenancies a clause covers are all legal or drafting judgments, so they're yours; Taylor is asked only for product decisions or when you're genuinely unsure. If you're unsure, don't decide and log it for later; Taylor may not read the log for a long time. Ask him in the chat, say what you need, and give a recommendation. Also ask him for product decisions the SOP doesn't settle (making something a default, a new kind of clause or feature, dropping a topic). Open each question with one plain sentence saying what the thing is, with an example, and label any risk that rests on case law or doctrine you haven't read as unread. If Taylor answers by asking why, answer in the chat, then re-ask with options that reflect his objections. [Taylor 2026-09-29; UT §6.2; Taylor 2026-10-01 (MI §6.2): 'This is a legal call under SOP rule 76, so make it yourself next time.'] [Fwd]

## Part 2. Sources and verification

11. **Primary official text only.** A statute is read from the state's official site or a host copy that prints history lines. A landlord-content site, a vendor lease or a law-firm summary is a lead, however many agree; several sites agreeing usually means copied content. A source's reliability in one state earns it nothing in the next. Where a search interface can't be paged, record the limit and claim an absence only from fully enumerated results. Test whether the official search honours quoted phrases (search a known two-word phrase in quotes); where it doesn't, record that and use AND batteries with every hit read in context. Before relying on a state's official search for an absence, prove what it indexes by searching a phrase already read verbatim in a section's body: a search that indexes only titles passes the nonsense-control test and still returns false negatives. [checklist 6; CLAUDE.md Aug 2026; KS retro 1: kslegislature.gov's search indexes titles and a snippet only; FL retro 3: Online Sunshine ignores quotes; CA retro 5: leginfo's paging couldn't be driven] [Fwd]
12. **Never mark a row VERIFIED on a summary.** If the controlling section was identified but not read, the row is NEEDS_REVIEW. A hit read in context during a full-text search is not a section read: open the whole section before marking the row VERIFIED. A fetch-tool summary is a lead, never currency evidence; read the page itself where a browser is available. [checklist 10, 45] [Fwd]
13. **Ask Taylor for text after two failed searches**, not a third. If you know the exact section, ask for it; if you only know the neighborhood, ask for the whole article or chapter. Take text Taylor supplies seriously and re-check against it immediately. When the official site and the host copies block automated reads, ask for every section you need in one batch, and check that each pasted section's number matches the one requested before relying on it. [checklist 8, 10, 25; TN retro] [Fwd]
14. **Save every primary text to disk as it's read** (one file per section or act under the state's source folder). Copy every count in the log from saved output. A draft without saved sources is recall and must be re-checked. Save each search battery (the exact pattern, hit counts, sections hit) as soon as it runs, before reading any hit. An in-page section extractor anchors on the section's own header line, not the first place its number appears (cross-references print the same number); fetch each relied-on section page twice and confirm its heading number matches the request. On a site where every page action needs approval (for example a court-rules host), batch the reads into one action and hash the text in that same action. When a saved file fails its hash, compare per-line lengths with the browser text to find the difference (writing tools strip trailing spaces and tabs). Where text comes through a browser the shell can't reach, prove each saved file matches what was read (for example, compare the browser's SHA-256 of the text with the saved file's). Where the prescribed proof isn't available (a browser tool that returns nothing), name the method actually used, such as a cross-read in two independent channels, and say it is weaker; never skip the step silently. After saving a bill's text, confirm it is the chaptered print (its print number and act title) before citing it as read as enrolled; a bill page can carry every print. Where a corpus is too large to export, run the batteries in the browser over the stored corpus, export each battery's full result and every relied-on section, prove the browser engine against the saved-section engine on a sample, and name it as a weaker method. A past edition relied on for a legal call is fetched, saved and hash-matched like current text; a fetch-tool summary of an old edition is a lead only. When a host copy sits behind a bot challenge, use the official code's own site rather than solving the challenge; when a document-access CAPTCHA appears, ask Taylor to solve it; when the shell's network is blocked, parse PDFs in the browser (pdf.js from cdnjs) and save the text with a hash check. Identify a browser download by its SHA-256, not its name (a background-tab download can land under a temporary name), and check the Downloads folder after any navigation reported as failed, since it may still have downloaded a file. When fetching statutes programmatically, confirm the character encoding before parsing (South Dakota's API serves UTF-16LE; read as UTF-8, every known positive silently fails). In the built-in browser, downloads land under temporary .tmp names and a download click can reload the crawl tab; export from a second tab on the same origin and identify files by size and SHA-256 [KY 5]. Generate a battery record's corpus label from the loaded index, not by hand [WA 7]. [checklist 64; UT §13; IL §1.1; PA retro; WY retro 5; GA retro 7; IA 2; SD retro 2; MT 3; NY 1, 6] [Fwd]
15. **Track which rows were written with the section open and which from recall.** Re-check only the recall rows, with the section open. [checklist 22] [Fwd]
16. **Currency comes from the history line, never from the section index or a heading.** A bill's status may support a row only if the bill page is saved and hashed like any other source [KY 3]. Cite an uncompiled act by act section and say the compiled number is pending; when an act adds a definition, check whether it renumbers the definitions section [OR 7: Or. Laws 2026, ch. 23 renumbered ORS 90.100 from (52) on]. Read the full history line and the revisor's recent-history block. Where the site prints no currency statement, say so and rely on history lines, version notes and the acts' effective-date clauses, listing any recent act whose clause wasn't read. Read the effective-date clause of every recent session law, even when the compilation already prints it (it may print law not yet in force), and compare it with the official act page and bill status; if they disagree, record both, ask Taylor (rule 76), state both dates in the education rows and flag it for the legal watch. Screen the state's latest general revisory (technical corrections) act for uncompiled changes to the sections relied on. Read the compilation's own currency statement and screen every later act in full text. Ask whether a special session met. Check whether bulk data lags and overlay the update pages: compare a recently amended section in the bulk or chapter download with its section page, and if the download lags, overlay every section in the session's official "code sections affected" list before searching. A government publication is not currency evidence on its own, and neither is majority agreement among reproductions. Where the official site gives each section version an effective date (version ids or metadata), take effective dates from it; it shows future-dated versions the history line alone doesn't. A real lease's citations (rule 33) are a cheap second probe: a stale one can confirm a renumbering. Where a site serves editions by a dated path, pull the same section from two editions and compare them; that turns "the URL says 2026" into evidence. When an enrolled act is extracted with a tool that drops formatting (pdf.js), recover underline and strike-through from the PDF's drawing marks before describing what the amendment adds or removes. Where a part has been repealed and reenacted with a future application date, the education row states both regimes and both dates, and the legal watch gets the changeover date. Overlay the session's sections-amended list on every section the rows cite, not only the core chapters, before drafting. A site's help-page currency statement can be stale; record it and rely on the history lines. Where a session-law page marks struck and added text in its markup, read the markup, not the plain text, which merges the two; and read the chaptered act's own section number before calling a codified number a misreading, since the codifier may renumber. Where a compiler's note makes a section effective only on a contingency ("effective upon the repeal of" another act), confirm the contingency before treating the section as law: an official compilation can print a dormant section with only a footnote (Florida's § 83.5615, a standby copy of the federal PTFA). Where a PDF text extraction of an enrolled act shows words the compiled code omits, assume possible strike-through, draft to the narrower reading until the PDF's marks are checked, and flag it. Treat a bill-status page's code-affected list and its date column as leads, never as the act: the list can carry the introduced bill's numbers, and the date is the last action, not approval [WV 4]. 18. **A bill is authority only once enacted.** Confirm it passed both chambers and was signed; an introduced draft, a failed bill or a pending overlap is not law. When a statute was amended by two acts in one session, read both and cite the session law. [checklist 17, 46; KS lesson 3] [Fwd]

A bounded battery licenses only a bounded claim: where a row's body says more than the corpus searched (a statewide "no form" from a search of one act), name the corpus in the body, not only in the notes. A keyword probe is a screen, not a verdict. Where the code has a data service or is served as whole-title files (XML or HTML), load the whole code and prove the load complete against the site's own title index. Load a throttled site sequentially, never in parallel, and never reuse the corpus tab for another page. Exclude a match on a section heading alone before counting a hit. State what was searched and what wasn't (rules, case law, local codes) and claim nothing beyond it. Record the basis of every absence: a whole-text search, a chapter read, or secondary agreement only. Where no loadable corpus exists, record which channels were tried and why each failed (egress policy, bot challenge, truncated PDF, no query URL), so the next pass neither repeats them blindly nor assumes a battery was run. Run a heading-only screen beside each absence battery, since a section can carry the term of art only in its heading. Write synthetic positives with the statute's own verbs and number style, and prefer a real saved section as the positive wherever one exists. Never use a `[^.]` proximity window across text that may hold dollar amounts or abbreviations ("$25.00", "Okla."). Where every positive for a battery is synthetic and the battery returns 0 hits, run a second battery on the everyday word for the problem ("overcrowding", not only "persons per bedroom") before recording an absence. On a search engine that drops true hits from long proximity chains (LexisNexis public-access codes did with three or more w/n terms), write the pattern as an AND of two OR-groups, and keep the known-positive test for each pattern. Generate each row's battery citation (number, hits, whether every positive passed) from the saved battery log rather than typing it; a battery whose positive failed is cited only as "recorded as failed, rerun as N". Prove a section parser complete against the chapter index before running any battery, not after (South Dakota's splitter missed three sections whose number and period sat on separate lines). Wrap every alternation in a group before adding a proximity limb, or the proximity binds only the first and last alternatives. When a real positive fails only because of a proximity window, rerun with a section-wide context filter; never drop the positive. A battery tool that indexes sections by number keeps every version of a section (current and future-dated), or its reruns silently drop hits. The heading-only screen reports a heading match whenever the section isn't counted, including when the body matched but failed the context filter. A battery scoped to some chapters is never cited as whole-code in a CONFIRMED ABSENT row; rerun it over the whole code first. Prove a crawler's link pattern against the site's own indexes before the first battery, including lettered chapters and odd encodings, and compare by unique section number, not by raw count (two-version sections inflate a table of contents); match anchors whitespace-tolerantly, since a tag can break across a line. 79. **Re-read the section before trusting a summary of it.** Where a row rests on secondary sources agreeing, read the cited section section-open before it ships: agreement proves a statute exists, not which subdivision says what. When summarising a subsection, parse it sentence by sentence and say which sentence each qualifier ("unless otherwise agreed", "except as provided") attaches to; a trailing qualifier belongs to its own sentence, not the whole subsection. Before reusing section files saved by an earlier pass, compare them by hash with the live text, since new versions may have taken effect in between; hash the normalised text (lowercased, whitespace collapsed with U+FEFF and U+00A0 treated as whitespace, any tool footer stripped from the saved file [VA circle-back 4], or the page's text content), not the raw bytes, since a site can change how it renders headings without changing the law. A basis names the artifact read ("section-open", "host copy with history line", "fetch-tool quote", "opinion snippet", "brief or secondary", or for an absence "statute-wide search with terms and hit counts"), not just a date, so a reviewer can grade it. A row whose `notes` record no basis can't be screened: report the count ("N of M rows record no basis") and read those rows section-open or list them; every new CITED row records its basis. Count from the row's `notes` and `lease_clause_basis` in `lease-clauses.csv`, not from the citations file, whose notes are a derived summary. Cite court rules from the current compilation, not an implementing order, since a later rewrite can renumber them (Texas Rule 510.6(a)(13) became (a)(11)). Where a row's effective or signing date rests on secondary sources, read the enrolled act, and apply the state's default effective-date statute when the act names no date (three agreeing sources gave Nevada's SB 114 the wrong signing date). Split the count between rows a research pass wrote and rows a library-wide pass created or renamed; the second group is fixed by carrying the source row's basis forward, which is a provenance repair, not a re-verification; where the section is reachable, also re-read the repaired row section-open, since a later rewrite can drop a defined term or qualifier its source carried [TN circle-back 2]. When re-reading a section first read from a host copy, compare its history line with the official one: a host copy can predate an amendment, and then the row is wrong, not merely unsourced. Check whether a cited section number with a letter suffix ("61.1f") is a separate section rather than a subsection ("61.1(f)"). Where two sentences of one subdivision give different figures for the same period, record the conflict on the row and take the reading whose error is cheaper, saying why [WY circle-back 1: W.S. 1-21-1210(a)(iii) says both 7 and 15 days]. Where a row rests on text the user supplied, check it against the enrolled act of any session law amending that article, not another compiled copy [WY circle-back 2]. When a row generalises a companion row's figure, screen the two together [WY circle-back 3]. A cross-reference that widens a penalty ("subsection (a) or (b)") is a qualifier and gets the same sentence-level parse [WY circle-back 4]. ### Step F. Optional clauses
54. **Find every optional clause the state's law allows, and offer each one.** Before offering a clause on the ground that the state supplies no statutory measure, search for the measure outside the landlord-tenant title; a damages chapter is the usual home [SD circle-back 1: SDCL ch. 21-3]. Recent activity in a clause's topic family is not a reason to defer an option the rule requires: rule 1 bars re-auditing finished work, not adding a row; where a library-wide pass has just switched a related clause off, offer the option and say in the row how the two fit together [OH circle-back 1]. An optional clause is a term the law lets a lease add or choose, for the landlord's benefit, but doesn't require. The landlord building a lease decides whether to use it, so the library offers every lawful one as optional, never as a default. Look for:
    - rights that exist only if the lease invokes them (a right the lease is silent on is lost);
    - statute wording that lets the lease decide ("if the lease so provides", "unless otherwise agreed in writing"; rule 50), including a retaliation safe harbour that turns on something "as agreed upon in the written lease" (Georgia's § 44-7-24(d)(2)(E) end-of-term notice);
    - waivers or exemptions the statute lets a tenant give up in the lease;
    - measures the statute doesn't set, which the lease can set instead (for example, a holdover charge where no statutory holdover measure exists, or for the cases a conditional measure leaves out: ask not only whether there is a statutory measure but for which cases and in what shape (a measure only for a willful holdover, or a lump sum rather than a daily rate, leaves a gap; and where the statutory measure applies only to a willful or bad-faith holdover, say what applies to the ordinary good-faith one and check whether the shared clause's self-limiting wording leaves that case with no figure));
    - landlord rights the statute leaves to contract (for example, ending the lease after a fire or casualty);
    - identifications the statute makes a trigger ("held and separately identified as", "furnished in writing specifically for this purpose"): the statute reads as a landlord duty, but the identification is itself an optional clause, and without it the regime doesn't apply (WY's utility deposit and abandoned-property notice address);
    - **tenant-caused damage** (always ask): if a tenant, occupant or guest causes damage that makes the home uninhabitable, what does the state's law give the landlord (repair costs, rent during repairs, lost rent if the lease ends), and can the tenant end the lease under a casualty statute anyway? Check each abatement or exit provision separately for a tenant-fault exception (casualty, essential services, landlord-breach termination, rent into court, which includes a city- or county-certified rent-suspension statute that pays into a bank escrow [PA circle-back 3: 35 P.S. § 1700-1], and statutory early-termination routes with their own fault rules, such as a domestic-violence exit, which the clause preserves by name [UT circle-back 1]); where the state offers both a casualty clause and a tenant-caused-damage clause, the persons whose fault counts are identical in both and cover the statute's own list [UT circle-back 2]: a state may have it in some and not others, which decides whether a no-abatement term would waive a statutory right. Read any landlord-paid-utility statute whole: a right to end the lease or pay and deduct when the landlord fails to pay a utility is an exit route too, and since it turns on the landlord's own failure it has no fault exception, so the clause must preserve it [IL circle-back 3: 765 ILCS 735/1]. Where the law covers it, record that in an education row; where the lease can lawfully fill a gap, offer the tenant-caused-damage clause (`tenant-caused-damage-tn` is the model); where the law bars it, record why.

    For each: if the law allows it, add it as an optional clause; if the law bars it or a court would likely void it, add nothing and record why. Where the state is an outlier in allowing something most states forbid, offer it narrowly (named items, the core duty carved out) rather than whole or not at all. **A lawful option the library declines to offer still gets an education row, never silence:** the row says the option is lawful, why it isn't offered, and that a landlord who wants it can add their own clause (and should take advice first). A note in the log alone isn't enough, because landlords never see the log. List every one found, with its citation and verdict, in the log's decisions section. Make these calls yourself when you're confident; if unsure, ask Taylor in the chat (rule 76).

    Examples from earlier states, all found by this rule and none of them a fixed checklist: a holdover charge (GA, NC, SC, TN, VA, AL, PA), landlord casualty termination (GA, NC, SC, AL, PA; CO likely void, so no clause), statutory waivers (TN, VA homestead, AL exemptions, KS exemptions, PA notice to quit; where the waiver statute excepts nothing on its face, as Kansas's K.S.A. 58-2530 doesn't, every carve-out in the clause is the drafter's judgment and the row says so [KS circle-back 2]), a crime-free or criminal-activity clause (AZ, NC, GA) and an eviction-fee clause (NC).
