# Steinoak State Research SOP

**Version 2.03, 2026-11-08 (1.0 approved by Taylor).** This is the one procedure every state pass follows. It replaces the "Instructions for the next state" list (instructions 1–66) in `lease-clause-decision-log-named-topic-checklist.md`, the method lessons scattered through the state logs, and Addenda K and L of `lease-clause-decision-log-architecture-review.md`. Each rule gives its source in brackets so the history can be traced; the reasoning lives there, not here.

**How this document is kept current**
- Rule numbers never change. A retired rule stays listed as "Retired, see rule N".
- **Who finishes what.** Claude Desktop's pass is finished when it delivers the handoff in Part 4. Everything after that is Claude Code's sync (Part 5), and Desktop doesn't need to track it.
- At sync, Claude Code reads the handoff's "Proposed SOP changes" list and the log for other lessons. It adds each one here as a rule or rejects it with a one-line reason in the change log. The sync isn't done until that's happened.
- **Claude Code assigns every rule's tag, never Claude Desktop.** **[Retro]** means the rule changes what a finished state's content should look like; **[Fwd]** means it's process only and applies to future work. When Claude Code adds a [Retro] rule, it adds a row to the conformance table and schedules a targeted check of each finished state against that rule only (a scalpel, not a re-audit). Claude Code does the checks it can from the repo; a check that needs statute text goes to that state's Desktop chat as a short, scoped prompt. Desktop runs a retro check only when handed one of those prompts.
- Claude Desktop reads this document at the start of every state pass and every circle-back. Claude Code checks each handoff against it.

## Part 1. Standing rules

1. **No re-audits.** A finished state is never re-scrubbed as a whole. Going back to fix or re-verify a specific row or topic is welcome: name it, say why, propose the narrow fix. Don't propose, plan or park anything "for the re-audit". [Taylor 2026-09-26; checklist 22] [Fwd]
2. **Never ask Taylor for landlord experience outside Colorado.** His experience is Colorado-only and already in the CO research. Scenario screens are generated by Claude (rule 23). [Taylor 2026-09-27] [Fwd]
3. **State law only.** Flag a municipal ordinance when you find one, but don't resolve it or let it into state-level clause text. [checklist 20] [Fwd]
4. **Coverage is "state law, verified", never "all law for the property".** There is no attorney review; say what was read and where the search stopped. [CO scope box; L.7] [Fwd]
5. **"Verified" is earned per state.** A blank `states` field means verified nowhere, and "universal" would need all 50 states verified. Tagging a second state needs the same primary-source rigor as the first. [CLAUDE.md Aug 2026] [Fwd]
6. **One curated answer per topic.** Where two versions of a clause reflect a legal-strategy choice rather than a fact about the law, ship one and keep the other inactive (`is_active` FALSE), with a note. Where the versions reflect a fact about the property or tenancy instead, ship both active in one `choice_group`, with the version lawful for everyone as `is_default` (rule 32), as `ca-tpa-coverage` and `co-part13-coverage` do. [WY Safe Homes; CO retro 6] [Fwd]
7. **The CSV is the fact; a log entry is not a library change.** If the log says a row exists, the row must exist. After writing rows, check the CSV itself. [L.3; ND lesson 7] [Fwd] [Fwd] A correction to what a row says is made in `bodyText`; a fix written only into `notes` is an open item, not a closed one (`edu-no-radon-tenant-disclosure-ne` kept saying § 76-2,120 covers "property sales, not leases" for a month after its notes were corrected). A row whose own notes downgrade it carries that status in `verification_status`; check both by script before delivery [NE-gaps 10].
8. **One Claude Desktop chat per state, reused for every circle-back.** At the start of any work in that chat: delete old output files (say what you deleted), treat the files Taylor uploads for this task as the only source of truth, and say so wherever something earlier in the chat conflicts with them. Name output files for their task (`lease-clauses-PA-delta.csv`), never a bare version number. [checklist 43] [Fwd]
9. **Settings:** Opus, high effort. Turn on research mode only for proof-of-absence confirmation, ambiguous or conflicting statute language, or a cross-chapter gap search, and say when and why you turn it on. [OH kickoff] [Fwd]
10. **When a question is about how the app behaves, ask Claude Code to run the code.** Don't reason from documentation, including CLAUDE.md and these logs; they have been wrong about the app before. [checklist 23] [Fwd]
76. **Work it out yourself first; if you're unsure, ask Taylor in the chat, right then.** Settle legal and drafting judgments yourself where you're confident, and record the reasoning in the log. Narrowing an optional clause, adding a saving sentence and choosing which tenancies a clause covers are all legal or drafting judgments, so they're yours; Taylor is asked only for product decisions or when you're genuinely unsure. If you're unsure, don't decide and log it for later; Taylor may not read the log for a long time. Ask him in the chat, say what you need, and give a recommendation. Also ask him for product decisions the SOP doesn't settle (making something a default, a new kind of clause or feature, dropping a topic). Open each question with one plain sentence saying what the thing is, with an example, and label any risk that rests on case law or doctrine you haven't read as unread. If Taylor answers by asking why, answer in the chat, then re-ask with options that reflect his objections. [Taylor 2026-09-29; UT §6.2; Taylor 2026-10-01 (MI §6.2): 'This is a legal call under SOP rule 76, so make it yourself next time.'] [Fwd]

## Part 2. Sources and verification

11. **Primary official text only.** A statute is read from the state's official site or a host copy that prints history lines. A landlord-content site, a vendor lease or a law-firm summary is a lead, however many agree; several sites agreeing usually means copied content. A source's reliability in one state earns it nothing in the next. Where a search interface can't be paged, record the limit and claim an absence only from fully enumerated results. Test whether the official search honours quoted phrases (search a known two-word phrase in quotes); where it doesn't, record that and use AND batteries with every hit read in context. Before relying on a state's official search for an absence, prove what it indexes by searching a phrase already read verbatim in a section's body: a search that indexes only titles passes the nonsense-control test and still returns false negatives. [checklist 6; CLAUDE.md Aug 2026; KS retro 1: kslegislature.gov's search indexes titles and a snippet only; FL retro 3: Online Sunshine ignores quotes; CA retro 5: leginfo's paging couldn't be driven] [Fwd] Where a site serves special-session acts only through a page wrapper that drops the session flag (palegis.us returns the regular-session act of the same number in its HTML, iframe and PDF forms; Claude Code confirmed all three at the 2026-11-08 sync), rely on an earlier section-open read and say so in the row; with no earlier read, the row is NEEDS_REVIEW and the log names the act so Claude Code can try another official route [PA-gaps 3]. [Fwd]

Where text comes through a browser the shell can't reach, prove each saved file matches what was read (for example, compare the browser's SHA-256 of the text with the saved file's). ### Step F. Optional clauses
54. **Find every optional clause the state's law allows, and offer each one.** Before offering a clause on the ground that the state supplies no statutory measure, search for the measure outside the landlord-tenant title; a damages chapter is the usual home [SD circle-back 1: SDCL ch. 21-3]. [OH circle-back 1]. An optional clause is a term the law lets a lease add or choose, for the landlord's benefit, but doesn't require. The landlord building a lease decides whether to use it, so the library offers every lawful one as optional, never as a default. Look for: When a lawful option is declined, check every education row that tells landlords to "put a clause in the lease" for that subject, and offer the clause or change the advice [AR 5]. An optional clause that has the tenant pay toward repairs says that the repairs and parts paid for belong to the landlord and may not be removed (Taylor, 2026-10-20) [MS 6].
    - rights that exist only if the lease invokes them (a right the lease is silent on is lost);
    - statute wording that lets the lease decide ("if the lease so provides", "unless otherwise agreed in writing"; rule 50), including a retaliation safe harbour that turns on something "as agreed upon in the written lease" (Georgia's § 44-7-24(d)(2)(E) end-of-term notice);
    - waivers or exemptions the statute lets a tenant give up in the lease;
    - measures the statute doesn't set, which the lease can set instead (for example, a holdover charge where no statutory holdover measure exists, or for the cases a conditional measure leaves out: ask not only whether there is a statutory measure but for which cases and in what shape (a measure only for a willful holdover, or a lump sum rather than a daily rate, leaves a gap; and where the statutory measure applies only to a willful or bad-faith holdover, say what applies to the ordinary good-faith one and check whether the shared clause's self-limiting wording leaves that case with no figure));
    - landlord rights the statute leaves to contract (for example, ending the lease after a fire or casualty);
    - identifications the statute makes a trigger ("held and separately identified as", "furnished in writing specifically for this purpose"): the statute reads as a landlord duty, but the identification is itself an optional clause, and without it the regime doesn't apply (WY's utility deposit and abandoned-property notice address);
    - **tenant-caused damage** (always ask): if a tenant, occupant or guest causes damage that makes the home uninhabitable, what does the state's law give the landlord (repair costs, rent during repairs, lost rent if the lease ends), and can the tenant end the lease under a casualty statute anyway? Where the law covers it, record that in an education row; where the lease can lawfully fill a gap, offer the tenant-caused-damage clause (`tenant-caused-damage-tn` is the model); where the law bars it, record why.

    For each: if the law allows it, add it as an optional clause; if the law bars it or a court would likely void it, add nothing and record why.
